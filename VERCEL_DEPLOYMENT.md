# CarePilot - Step-by-Step Vercel Deployment & Environment Variables Guide

This document provides a complete, step-by-step guide to deploying **CarePilot** on **Vercel** with **Vercel Postgres (Neon)** or **Supabase**, including all exact environment variables and automated database setup details.

---

## 1. Quick Overview: How CarePilot Deploys Automatically

CarePilot includes a custom zero-config build runner ([`scripts/build.mjs`](file:///c:/Users/nahid/OneDrive/Desktop/Regard%20Tech/carePilot/scripts/build.mjs)) that executes automatically on Vercel when you deploy:

1. **Auto Environment Variable Mapping**: It detects Vercel Postgres / Neon environment variables (`POSTGRES_PRISMA_URL` and `POSTGRES_URL_NON_POOLING`) and maps them to Prisma's required `DATABASE_URL` and `DIRECT_URL`.
2. **Auto Database Schema Sync**: It executes `prisma db push --skip-generate` to create all 15+ PostgreSQL tables (`users`, `doctors`, `specialties`, `branches`, `appointments`, `diagnostic_tests`, `articles`, `notices`, `reports`, etc.).
3. **Auto Seeding**: It executes `prisma/seed.ts` to automatically populate demonstration doctors, branches, diagnostic tests, and patient accounts.
4. **Next.js Production Build**: Compiles and pre-renders static & dynamic bilingual pages.

## 3. Environment Variable Details & Values

| Variable Name | Environment | Required? | Purpose / Value |
| :--- | :--- | :--- | :--- |
| `DATABASE_URL` | All (Prod, Preview, Dev) | **Required** | Pooled database connection string (e.g. `POSTGRES_PRISMA_URL` or Supabase PgBouncer port `6543`). |
| `DIRECT_URL` | All (Prod, Preview, Dev) | **Required** | Direct database connection string (e.g. `POSTGRES_URL_NON_POOLING` or Supabase direct port `5432`). |
| `NEXTAUTH_SECRET` | All | **Required** | Any random 32-character string for JWT session encryption (e.g. `carepilot_secret_1234567890_key_auth`). |
| `AUTH_TRUST_HOST` | All | **Required** | Must be set to `true` for NextAuth to trust Vercel serverless proxies. |
| `NEXT_PUBLIC_SITE_URL` | All | **Required** | Public domain of the deployed site (e.g., `https://regards-care-pilot.vercel.app`). |
| `NEXTAUTH_URL` | All | **Required** | Same as `NEXT_PUBLIC_SITE_URL`. |
| `NEXT_PUBLIC_SANITY_*` | All | Optional | Sanity CMS Project ID and API tokens. If omitted, app uses high-quality demonstration dataset. |
| `NEXT_PUBLIC_CLOUDINARY_*` | All | Optional | Cloudinary media upload credentials for doctor photos & branch imagery. |

## 4. Step-by-Step Vercel Deployment Instructions

### Step 1: Push Code to GitHub
Ensure all latest commits are pushed to your remote repository:
```bash
git push origin main
```

---

### Step 2: Import Project in Vercel
1. Log in to **[vercel.com](https://vercel.com)**.
2. Click **Add New...** → **Project**.
3. Select your GitHub repository (**`regardstech/CarePilot`** or **`naimur-rooted/Regards_carePilot`**).
4. **Framework Preset**: `Next.js` (Auto-detected).
5. **Root Directory**: `./` (Default).

---

### Step 3: Create Free Postgres Database inside Vercel Storage
1. In your Vercel project dashboard, click the **Storage** tab at the top.
2. Click **Create Database** → Select **Postgres (Neon / Vercel Postgres)**.
3. Choose a name (e.g. `carepilot-db`) and select your region (e.g., *Singapore `ap-southeast-1`*).
4. Click **Create** and select **Connect to Project** → **`CarePilot`**.

---

### Step 4: Configure Environment Variables in Vercel
1. Go to **Settings → Environment Variables** in your Vercel project.
2. Add the required variables:
   - `DATABASE_URL` = `${POSTGRES_PRISMA_URL}` *(or paste the string from `.env.local` tab in Storage)*
   - `DIRECT_URL` = `${POSTGRES_URL_NON_POOLING}` *(or paste the string from `.env.local` tab in Storage)*
   - `NEXTAUTH_SECRET` = `carepilot_secret_1234567890_key_auth`
   - `AUTH_TRUST_HOST` = `true`
3. Check **Production**, **Preview**, and **Development** for each variable.
4. Click **Save**.

---

### Step 5: Trigger Deployment
1. Go to **Deployments** tab.
2. Click **`...`** (three dots) on the latest commit → Select **Redeploy**.
